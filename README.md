# Rusted Warfare Unit Guessing Experiment

这是一个 DeepSeek Harness + GPT 协作进行的《铁锈战争》单位猜测实验。

## 角色

### User
- 裁判。
- 私下选择一个 Rusted Warfare 单位。
- 向 DeepSeek 提供单位特征和反馈。
- 不提前向任何 Agent 公布答案。

### DeepSeek
- 主猜测者。
- 根据用户提供的线索进行推理。
- 可以提出问题。
- 每轮将推理、猜测和用户反馈写入 `turns/`。
- 阅读 GPT 的上一轮反馈后继续下一轮。

### GPT
- 协作分析者。
- 只依据 GitHub 中已经公开的信息工作。
- 检查 DeepSeek 的推理错误、遗漏候选和错误知识。
- 为 DeepSeek 提供下一轮最有价值的分析方向。
- 不主动向用户索要真正答案。

## 胜利条件

DeepSeek 最终明确猜出用户私下选择的单位。

## 核心规则

1. 真正答案不得提前写入 GitHub。
2. 两个 Agent 只能依据已经公开的线索推理。
3. DeepSeek 是主要猜测者。
4. GPT 主要承担知识补充、纠错和提示。
5. 每一轮必须留下记录，以便之后复盘整个协作过程。

## 实验修订（Experiment Amendments）

> 以下条目由**实验 1 复盘**产生，用于修补原设计中的实际漏洞。
> 它们**修正**上述规则的部分表述，效力高于原始表述。原始表述保留在上方，不做静默改写。

### 修订 A — 候选名单同样不得入库（修正规则 1）

**原表述冲突**：原设计要求 DeepSeek「每轮将推理、**候选单位**、猜测和用户反馈写入 `turns/`」，
但规则 1 又要求「真正答案不得提前写入 GitHub」。**当答案本身就在候选名单里时，两条要求直接矛盾。**

**实验 1 的实际后果**：正确答案「Mech Engineer」早在 commit `2306b0e` 就以候选身份进入公开仓库，
早于 Round 2 提问。事后公布结果时，**任何人回看历史即可发现答案始终在候选列表中**，盲测设计已被削弱。

**修订内容**：

- **候选单位名单不入库。** 候选池仅存在于 DeepSeek 的推理文本与聊天中。
- 入库内容限于：提问、已确认线索、被排除候选、推理框架、轮次结果。
- 命中后公布答案时，**必须声明该名称此前是否曾作为候选出现过**。

### 修订 B — 开局禁用固定选项

**实验 1 的失误**：Round 1 的 Q1 把「陆行」定义为「**轮式或履带**」，漏掉**步行机甲**整条线，
导致 User 回答「没有严格符合的选项」，浪费一轮；并险些使正确答案不在候选池内。

**修订内容**：**DeepSeek 的知识缺口不得成为选项边界。** 前几轮一律采用**开放式提问**，由 User 用自己的话描述。

> **精度补充（经 GPT 提醒后修正）**：开放题的收益**不是**「信息量一定比选择题更高」——
> 回答的长度与精度由裁判决定，无法预设。它的真实收益是：
> **不依赖 DeepSeek 的知识完整性，从而避免 DeepSeek 的知识缺口变成搜索空间的边界。**
> （实验 1 的失效模式正是后者。）

### 修订 C — GPT 写入须同守纪律

GPT 在 **Codex 模式**下具备 git 身份，**可直接写入本仓库**。此时 GPT 的候选名单会像修订 A 所述那样直接进入公开历史。

**修订内容**：GPT 写入本仓库时，**只写分析与纠错，不写候选单位名单、不写答案**。
