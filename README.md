# Rusted Warfare Unit Guessing Experiment

这是一个 DeepSeek Harness + GPT 协作进行的《铁锈战争》单位猜测实验。

## 角色

### User
- 裁判。
- 私下选择一个 Rusted Warfare 单位。
- 向 DeepSeek 提供单位特征和反馈。
- 不提前向任何 Agent 公布答案。

### DeepSeek
- 主猜测者。
- 根据用户提供的线索进行推理。
- 可以提出问题。
- 每轮将推理、猜测和用户反馈写入 `turns/`。
- 阅读 GPT 的上一轮反馈后继续下一轮。

### GPT
- 协作分析者。
- 只依据 GitHub 中已经公开的信息工作。
- 检查 DeepSeek 的推理错误、遗漏候选和错误知识。
- 为 DeepSeek 提供下一轮最有价值的分析方向。
- 不主动向用户索要真正答案。

## 胜利条件

DeepSeek 最终明确猜出用户私下选择的单位。

## 核心规则

1. 真正答案不得提前写入 GitHub。
2. 两个 Agent 只能依据已经公开的线索推理。
3. DeepSeek 是主要猜测者。
4. GPT 主要承担知识补充、纠错和提示。
5. 每一轮必须留下记录，以便之后复盘整个协作过程。

## 实验修订（Experiment Amendments）

> 以下条目由**实验 1 复盘**产生，用于修补原设计中的实际漏洞。
> 它们**修正**上述规则的部分表述，效力高于原始表述。原始表述保留在上方，不做静默改写。

### 修订 A — 候选名单同样不得入库（修正规则 1）

**原表述冲突**：原设计要求 DeepSeek「每轮将推理、**候选单位**、猜测和用户反馈写入 `turns/`」，
但规则 1 又要求「真正答案不得提前写入 GitHub」。**当答案本身就在候选名单里时，两条要求直接矛盾。**

**实验 1 的实际后果**：正确答案「Mech Engineer」早在 commit `2306b0e` 就以候选身份进入公开仓库，
早于 Round 2 提问。事后公布结果时，**任何人回看历史即可发现答案始终在候选列表中**，盲测设计已被削弱。

**修订内容**：

- **候选单位名单不入库。** 候选池仅存在于 DeepSeek 的推理文本与聊天中。
- 入库内容限于：提问、已确认线索、被排除候选、推理框架、轮次结果。
- 命中后公布答案时，**必须声明该名称此前是否曾作为候选出现过**。

### 修订 B — 开局禁用固定选项

**实验 1 的失误**：Round 1 的 Q1 把「陆行」定义为「**轮式或履带**」，漏掉**步行机甲**整条线，
导致 User 回答「没有严格符合的选项」，浪费一轮；并险些使正确答案不在候选池内。

**修订内容**：**DeepSeek 的知识缺口不得成为选项边界。** 前几轮一律采用**开放式提问**，由 User 用自己的话描述。

> **精度补充（经 GPT 提醒后修正）**：开放题的收益**不是**「信息量一定比选择题更高」——
> 回答的长度与精度由裁判决定，无法预设。它的真实收益是：
> **不依赖 DeepSeek 的知识完整性，从而避免 DeepSeek 的知识缺口变成搜索空间的边界。**
> （实验 1 的失效模式正是后者。）

### 修订 C — GPT 写入须同守纪律

GPT 在 **Codex 模式**下具备 git 身份，**可直接写入本仓库**。此时 GPT 的候选名单会像修订 A 所述那样直接进入公开历史。

**修订内容**：GPT 写入本仓库时，**只写分析与纠错，不写候选单位名单、不写答案**。

> **以下 D～L 由实验 2 复盘产生**，提案方标注在每条末尾。
> 其中 E、F 两条的**绝对化表述已按 Sol 的验收修正**（Sol 指出「最高优先」不等于「不可能错」，
> 且禁止提出映射假设会禁掉有用的推理）。**由 User 裁定采纳。**

### 修订 D — 判定前，正式猜测的名称不入库

**审计依据**：实验 2 中，`bugSpore` 于 commit `6b74101` **已被写入公开仓库**，
而裁判判定在**其后**才公布。即**猜测名称在判定前已入库**，违反规则 1。

**根因不是疏忽**：规则 1 说「答案不得提前写入」，但**未规定「猜测本身算不算答案」**；
而协议又要求「DeepSeek 写 `turns/00N_deepseek.md`」。两条要求在「猜测已接近答案」时冲突。

**修订内容**：

- **判定前**，正式猜测的具体名称不得入库；入库只写「已提交一猜，待判定」。
- **判定后**，再于结果文件中记录该名称。
- 若需保留「判定前已提交」的可审计性，采用**修订 K 的承诺方案**。

> 提案方：DeepSeek（实验 2 审计）。Sol 明确支持。

### 修订 E — 证据分层，但**不规定哪一层永远为真**

**依据**：实验 2 的 `experimentalGunship` 被否决，直接原因是 DeepSeek 用多条
**二级（数据推断）** 证据去对抗一条 **一级（裁判行为观察）** 证据。

| 级别 | 来源 | 例（实验 2 实例） |
|---|---|---|
| **一级：行为观察** | 裁判的直接经验/操作 | 「我曾后悔给它的一个指令，想要撤销发现不能」 |
| **二级：数据/文献推断** | 代码字段、wiki、二手资料 | `movementType: HOVER`、`builtFrom` 注释 |

**修订内容**：

- 两层冲突时，**一级（行为观察）为最高优先证据**——二级证据不得**自行改写**裁判原话。
- **但「最高优先」不等于「不可能错」**：裁判的直接体验仍可能有**记忆误差或语义歧义**。
- **因此两层冲突时，正确动作是「标记冲突并向裁判澄清」，而不是判定哪一层永远为真。**

> 提案方：Sol（第 2 节）+ DeepSeek。**绝对化表述已按 Sol 验收修正。**

### 修订 F — 允许提出「用语 ↔ 字段」映射假设，但必须标注为假设

**依据**：DeepSeek 曾把裁判的「在地面上跑」**静默映射**为「`movementType` 属于地面类」，
并在后续打勾时把它当作已确认事实——这是实验 2 的关键失误之一。

**修订内容**：

- Agent **可以**提出映射假设（例：「这里的『变成』可能对应 `convertTo`」）。
- **必须明确标注为假设**，**不得静默升级为已确认事实**。
- 两种用语之间的对应关系，**最终只能通过向裁判提问来建立**。

> **原提案（禁止翻译）过于严格，已按 Sol 验收放宽为「标注假设」。**

### 修订 G — 不得用无法裁决的推测消解一级线索

**依据（DeepSeek 自评，比「计数法」更严重）**：实验 2 中 DeepSeek 曾写下
「`Undeploy` 是否在 UI 呈现取决于运行时行为，无法从数据单独证实」——
**然后照样给这一条打了勾**。

**这不是计数法，而是编造一个无法证伪的理由去消解一级证据**，
把本该否决猜测的矛盾变成了「已解释」。

**修订内容**：若某条冲突所需的解释**超出当前证据能力**，正确做法是
**保留该冲突为「未解决」**，而不是给它一个「可能如此」的说法然后继续。

> 提案方：DeepSeek。

### 修订 H — 同一轴连续 3 轮，强制切换正交维度

**依据**：实验 2 前半段连续追问「怎么转化、何时转化、转化成什么」，
全部在同一机制轴上细分；**身份轴（阵营、生产建筑、外观、造价、单位族）进入太晚**，
是耗时 10 轮的主因。

**修订内容**：在 `STATE.md` 中设**显式计数器**（如 `same_axis_streak`）；
达到 **3** 即**禁止**下一轮再问同一轴。

> 提案方：Sol（第 3 节）。

### 修订 I — Agent 书面承认知识不可靠后，下一轮必须先查原始数据

**依据（DeepSeek 自评）**：DeepSeek 在 `turns/003_deepseek.md` 中**明确写过**
「对《铁锈战争》完整单位名册的知识存在不确定」，
**但之后仍凭记忆连续问了 4 轮机制问题**（Round 4～7）。
**已承认盲区却未据此改变行为**——说明自觉不够，需触发器。

**修订内容**：一旦 Agent 在任何文件中写下「不确定 / 不可靠」等表述，
**下一轮必须先检索原始数据或请协作方补知识，不得继续凭记忆提问**。

> 提案方：Sol + DeepSeek。

### 修订 J — 禁止在同一回合内替换已推送的猜测

**依据**：实验 2 Round 10 中，DeepSeek 先猜 `modularSpider` 并**已推送**（commit `a8904bc`），
随后在同一回合内自行降级为 `bugSpore`。这使「正式猜测次数」的统计产生歧义（3 次还是 4 次）。

**修订内容**：**禁止在同一回合内替换已推送的猜测**；若需修正，**应作为新回合记录**，
以便「猜测历史」可被审计。

> 提案方：DeepSeek。Sol 认可（「会破坏审计历史」）。

### 修订 K — 一回合一个承诺；未命中的承诺也须公开

**目标（双重）**：判定前不泄露答案，判定后又能审计「猜测确实提前存在」。

**承诺方案**：

1. DeepSeek 在本地生成**明文猜测** + **高熵随机 nonce/秘密盐（≥128 bit）**；
2. 计算 `H = SHA-256("rw-unit-guess|exp=<实验号>|round=<回合号>|guess=<规范化猜测串>|salt=<hex盐>")`
   （UTF-8、LF 换行、无尾随换行）；
3. 判定前**只把 `H` 与格式说明写入仓库**；
4. 判定后公开明文与盐，任何人可独立复算 `H`。

**报文的可选增强**：判定前把「明文 + 盐」**另行交给裁判本人**（不入仓库），
以避免本地丢失导致承诺永久不可验证——**这是保管与审计增强，不是密码学上的必需**。

**必须防止的漏洞（shotgunning）**：哈希承诺**不能**防止「同时押多个单位、判定后只揭示命中的那个」。
**因此：一个回合只允许提交一个承诺**，且**未命中的承诺在实验结束后也必须公开**。

**能力边界（诚实声明）**：承诺只能证明「某个明文在某个时间点之前已存在」，
**不能证明猜测不是事后构造的**。

> 提案方：Sol（承诺方案）+ DeepSeek（保管增强、shotgunning 约束与边界声明）。
> Sol 验收指出：原方案在密码学上成立，DeepSeek 关于「失效」的表述有误，已按此改写。

### 修订 L — 知识补充方提供「机制/方向」，不直接给候选名称

**依据（实验 2 有效性的来源）**：本轮分工之所以有效，是因为满足三个条件：

1. **一方有明确盲区**（DeepSeek 缺 `dieOnConstruct` 知识，且本机网络被拦截无法自查）；
2. **另一方提供可检验的假设**（Sol 说「这是一条独立路径」，**而不是直接给答案**）；
3. **提出假设的一方不负责验证** —— 验证由 DeepSeek 用**原始数据穷举**完成。

**正因为 Sol 给的是「机制类别」而非答案，DeepSeek 才必须回到 `assets\units\` 自己找，
并最终把 `bugSpore` 与 `bugFly` 区分开。**

**修订内容**：知识补充方**应提供机制 / 类别 / 检索方向**，而非直接提供候选名称。
若确需给出名称，**应同时给出一项可独立复核的判据**，供主猜测者验证。

> 提案方：DeepSeek。

## 协作通道（实验 2 起）

- **GPT 侧**：GPT-5.6 Sol，具备 git 身份，可**直接读写本仓库**（声明见 `GPT_SOL_ONLINE.md`）。
- **备用写入通道**：`tools/bridge.ps1`（已验证）。原生写入权限排查见 `tools/GPT_GITHUB_WRITE_FIX.md`。
- **并发写入约定**：各写独立文件 + 写前 `git fetch` + push 冲突时 `rebase` 重试；
  **`STATE.md` 仅由一方负责汇总**，另一方以独立文件提出意见，不直接改写。

## 回合文件格式

DeepSeek：

`turns/001_deepseek.md`

GPT：

`turns/001_gpt.md`

然后：

`turns/002_deepseek.md`

`turns/002_gpt.md`

依此类推。回合编号**跨实验连续**，不因新实验重置。
