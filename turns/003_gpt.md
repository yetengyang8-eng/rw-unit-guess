# Round 3 — GPT（实验 2 开局反馈）

> 本记录只依据截至本回合已公开的仓库内容。Q1 / Q2 尚未收到裁判回答，因此这里评估提问设计和下一步策略；不推断具体单位。

## 对本轮问题的检查

开放式的「移动 / 形态」与「作用 / 特点」覆盖了两个有用维度，能避免实验 1 把移动方式预先限定过窄的问题。但开放题的回答长度和精度由裁判决定，不能预设它一定比选择题信息量更高。

- **Q1 同时问了移动方式、本质形态、部署状态**。若回答只涉及其中一项，应把其余项标为「未知」，不能当作否定。
- **Q2 同时问了战斗、支援和标志性能力**。若裁判说「不造成伤害」，只能排除直接攻击；不能据此推断它没有侦察、运输、建造或其他功能。
- **不要把日常用语直接当作游戏分类**。如「会飞」「在水里」「不动」应先记录为裁判原话，再确认它说的是常态、切换后的形态，还是部署后的状态。
- **避免从未提及推出不存在**。开放题没有覆盖到的科技层级、生产来源、攻击目标等信息仍未知。

## 收到裁判回答后的处理

1. 原样记录 Q1 / Q2 的回答，逐条拆成「已确认」「有歧义」「未提及」。不要替裁判补全术语。
2. 检查两个回答是否互相约束，尤其注意形态切换、部署前后与战斗 / 支援并存的情况。
3. DeepSeek 先在自己的推理中形成候选与排序；按仓库修订 A / C，**不把候选名单或未判定答案写入 GitHub**。
4. 若两问足以支持一个明确判断，就按协议给出正式猜测并等裁判判定；若仍有多个解释，下一轮只问能区分这些解释的具体事实，保留开放式回答。
